## Область работ (Media Library → Files и связанное)

Реализовать в реальном продукте перечисленное. Для каждого пункта в прототипе есть рабочий референс поведения; сверяйся с продом (`app.subsub.io`) и Figma/Storybook, где применимо.

### 1. YouTube-флоу разделён на два независимых экшна
Раньше был один «Publish to YouTube» (генерация метаданных + публикация). Теперь **два действия**, обе на одной модалке генерации метаданных (Title 1/N, Description, Tags, Hashtags, Timecodes, Regenerate, per-field Copy):
- **Send to YouTube Studio** — в меню «⋮» видео + единственный акцентный CTA (красная кнопка) в шапке превью видео. Флоу с выбором канала (лейбл **«Send to»**, дропдаун мок-каналов + «Connect another channel» → мок Google sign-in + empty-state «No connected channels yet»). Финал — **отправка черновика в YouTube Studio**: success «Sent to YouTube Studio» + кнопка «Open in YouTube Studio» (публикации вживую тут нет).
- **Metadata** — отдельный пункт «⋮» (только видео, БЕЗ дубля в шапке превью). Та же генерация, **без шага канала и без отправки**. Футер «Cancel + Save metadata».
- Прод-аналог: на проде это пункт «Create metadata» и общий флоу — разнести на два.

### 2. Артефакт метаданных
- По «Save metadata» (и **также** при финале «Send to YouTube Studio») сохраняется файл `<имя видео> - metadata.txt` в папку **Metadata** в корне Media Library (папка создаётся автоматически, если её нет). Повторное сохранение — перезапись.
- Внутри `.txt` — секции Title (все варианты) / Description / Tags / Hashtags / Timecodes простым текстом.
- Файл — категория document/text, обычное меню «⋮», превью с Copy и Download .txt.

### 3. Транскрибация (net-new — на проде пункта Transcribe нет; построено по образцу прод-конвертации)
- Пункт «⋮» **Transcribe** (видео и аудио) → модалка: язык исходной транскрипции (дефолт **Auto-detect**) + мультиселект **«Translate transcription to»** (поиск + чекбоксы) → отдельный `.srt` на каждый язык.
- Топбар-бейдж фоновой задачи `⟳ Transcribing N` → `✓ Transcribed` (indigo, по образцу прод-`Converting`/`Converted`, но другим цветом) + попап «File transcription» с прогресс-баром **на каждый файл** и кнопкой «Go to file».
- Нотификация о завершении + инкремент бейджа на колокольчике.
- Результат: `Transcriptions/<имя видео>/<код языка>_<имя видео>.srt` (вложенная папка на видео). После завершения пункт «⋮» у видео меняется на **Review transcription** (открывает результат).
- Превью `.srt` — реплики с таймкодами + Copy / Download .srt.

### 4. Медиатека — навигация и список
- **Вложенные папки** с хлебными крошками (N уровней): root → папка → под-папка. Папки Analytics/Music (примеры) + авто-папки Transcriptions/Metadata.
- **Инфинайт-скролл** списка файлов с лоадером (вместо пагинации), счётчик «N folders · M files».
- **Фильтр по типу файла** (дропдаун с чекбоксами) рядом с поиском.
- Таблица обёрнута в плоскую surface-карточку (по `BaseTable`).
- Превью файла в строке 70×48: видео — кадр с play; остальные типы — иконка на сером фоне.

### 5. Модалки превью (7 типов) — единый светлый хедер
- На проде шапки модалок несогласованы (часть — тёмные, image — PhotoSwipe). В прототипе приведены к **одному светлому** паттерну: белый фон, цветной icon-badge по типу, имя файла, единый close + action-bar (Share/Download; у видео — Send to YouTube Studio).
- Рендер контента — нативными средствами браузера (video/audio/img/iframe-pdf/код); docx/xlsx — заглушки.

### 6. Шеринг
- Модалка «Share this file»: Copy link, поиск получателей с подсказками («Already added»), список доступа (имя + email, Revoke + подтверждение), строка «Anyone with the link · Can view».

### 7. Нотификации (поповер по колокольчику)
- Обычные + тип «поделился файлом» (иконка типа файла фиолетовая + «[Имя] shared [файл] with you» + Dismiss/View). Бейдж-счётчик непрочитанного.

### 8. Публичная страница шаренной ссылки (net-new — в проде такой страницы нет)
- `shared-file-<type>.html` по каждому типу (video/audio/pdf/spreadsheet/archive): лёгкий шелл (лого + «Sign up free»), атрибуция «Shared by …», карточка превью, промо-баннер, фиолетовая кнопка Download. Оценить, нужна ли такая гостевая страница в реальном продукте (в проде шеринг внутренний).
