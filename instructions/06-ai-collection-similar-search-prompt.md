# ФАКТУРА

## 1. Что это и зачем

Одна механика — **sourcing коллекции**: пользователь описывает, какие каналы ему нужны, система сама находит их на YouTube и складывает в коллекцию. У механики два входа:

| Вход | Смысл | Что предзаполнено |
| --- | --- | --- |
| **AI collection** | «Найди мне каналы по описанию» | ничего, описание пишет пользователь (или автогенерация по ссылке) |
| **Find similar channels** | «Найди похожие на эти» | выбранные в таблице каналы становятся reference channels, описание генерируется по ним |

Оба входа открывают одну и ту же модалку `Set up collection sourcing` — отличается только режим (`single` / `refs`). Результат в обоих случаях один: коллекция (новая или существующая), в которую дописаны найденные каналы.

Зачем: сейчас единственный способ набрать коллекцию — искать каналы руками в Basic data и добавлять их по одному. Sourcing закрывает сценарий «я знаю, кого хочу, но не знаю их названий».

## 2. Точки входа

1. **Basic data → кнопка `AI collection`** (акцентная AI-кнопка справа в строке поиска, рядом с `Filters`). Открывает модалку в режиме `single`.
2. **Basic data → выбор каналов чекбоксами → в футере выбора кнопка `Find similar channels`.** Открывает ту же модалку в режиме `refs`:
   - выбранные каналы сразу добавлены как reference channels (с аватарами из таблицы);
   - имя новой коллекции подставлено как подсказка: `Similar to <первый канал> +N` (пользователь может переписать);
   - генерация описания стартует сразу.
3. **My collections → кнопка `AI collection`** — тот же вход, что п. 1.
4. На проде уже существует страница похожих каналов у канала (`Similar channels`) и эндпоинт `GET /new-app/api/v1/analytics/basic-data/channel/{id}/similar-channels`. В прототипе этот вход не рисовали — нужно решить, связываем ли его с этой механикой (см. «Открытые вопросы»).

## 3. Модалка `Set up collection sourcing`

Заголовок: `Set up collection sourcing`
Подзаголовок: `Describe the channels you want — we'll find and collect them for you.`
Шапка не скроллится вместе с телом, отделена разделителем. Кнопки футера: `Cancel` и `Start sourcing`.

### 3.1 Назначение (куда попадут каналы)

Два взаимоисключающих состояния:

- **Коллекций ещё нет** — одно поле `Collection name *`, плейсхолдер `e.g. Fortnite gamers — US`. Найденные каналы создадут первую коллекцию.
- **Коллекции есть** — лейбл `Collection`, дропдаун (`Select collection`) со списком коллекций + чёрная кнопка `+` справа. В футере списка пункт `Create new collection`.
  - `Create new collection` и `+` открывают вложенную модалку создания коллекции (`Create collection`, поле имени, кнопка `Create`). Имя предзаполняется подсказкой из референсов: `Similar to <канал> +N`.
  - Коллекция, по которой уже идёт подбор, в списке **недоступна для выбора** (disabled).

Правило: коллекция, только что созданная из этой модалки, считается новой AI-коллекцией. Выбор уже существующей коллекции — это режим дописывания (append), новая коллекция не создаётся и AI-коллекцией она не становится.

### 3.2 Reference channels (режим `refs`)

Лейбл `Reference channels`. Пустое состояние: `No reference channels yet — add one to draft the description automatically.`

- Добавленный референс — чип: аватар с инициалом и цветом канала, название, `×` для удаления.
- В покое видна только кнопка `Add channel`; по клику она разворачивается в комбобокс с плейсхолдером `Paste a channel link or type a name` и кнопкой `Add` (заблокирована, пока поле пустое).
- Ввод **названия** → выпадающий список каналов из базы (до 6 подсказок, уже добавленные не показываются, если ничего не нашлось — `No channels found`).
- Ввод **ссылки** (`https://…`, домен, `@handle`) → подсказки не показываются, доступна кнопка `Add`.
- Дубли не добавляются (сравнение по названию без учёта регистра).
- Клик вне поля скрывает подсказки, пустое поле сворачивается обратно в кнопку.
- **Любое изменение набора референсов перезапускает генерацию описания.** Если удалили все — генерация отменяется.

### 3.3 Описание

Лейбл `Describe the channels you're looking for`, textarea (3 строки).
Подсказка под полем: `We turn this into real YouTube search queries in your audience's language and use it to judge whether a channel fits.`

Четыре состояния поля:

| Состояние | Поведение |
| --- | --- |
| Покой | В плейсхолдере по кругу меняются примеры: `e.g. Fortnite gamers with a US audience`, `e.g. Turkish TV series channels`, `e.g. channels that cook Thai food`, `e.g. budget-phone tech reviewers`. Примеры живут **только в плейсхолдере**, в значение поля не попадают. |
| Ввод | Ротация примеров останавливается сразу, плейсхолдер гасится. |
| Генерация | Строка-лоадер со спиннером и сменой сообщений: `Reading the channel…` → `Finding similar creators…` → `Picking examples…` → `Almost there…` |
| Готово | Сгенерированный текст подставлен в поле, пользователь может его править. |

Как запускается генерация:

- **Режим `single`:** под textarea строка `Paste a channel link to autofill` + кнопка `Auto-fill`. Кнопка активна только при непустой ссылке.
- **Режим `refs`:** строка автозаполнения скрыта, описание генерируется автоматически при каждом изменении набора референсов.

Смысл генерации: по ссылке или набору референсов получить черновик описания «каналы как эти» на человеческом языке. В прототипе текст собирается по шаблону (например `Channels similar to <названия> — same niche, format and audience language. Mid-size creators publishing regularly with steady growth; exclude compilations and reuploads.`) и различается для youtube-ссылок и ссылок на twitch/tiktok/instagram. **На проде это должен быть вызов LLM** — шаблон в прототипе только чтобы показать сценарий.

### 3.4 Advanced filters

Свёрнутая секция `Advanced filters` (раскрывается по клику, в свёрнутом виде рядом с заголовком — краткая сводка активных значений).

| Поле | Значение по умолчанию |
| --- | --- |
| `Min subscribers` | 10 000 |
| `Min videos` | 0 |
| `Min total views` | 0 |
| `Min avg views (last 3 videos)` | 0 |
| `Max days since last video` | 0 |

`0` = фильтр не применяется. Активные значения показываются чипами в формате `subs ≥ 10,000`, `videos ≥ 50`, `views ≥ 1,000,000`, `avg ≥ 10,000`, `last ≤ 30d` — теми же чипами они потом видны в представлении коллекции.

### 3.5 Валидация и запуск

`Start sourcing` заблокирована, пока не выполнены оба условия:

1. задано назначение (имя новой коллекции или выбранная коллекция);
2. заполнено описание **или** есть источник (ссылка в режиме `single` / хотя бы один референс в режиме `refs`).

Тосты при попытке запустить с незаполненным:

- нет назначения: `Select a destination collection` (если коллекции есть) / `Name the collection first` (если это первая коллекция);
- нет источника: `Add at least one reference channel` (режим `refs`) / `Describe the channels or paste a channel link` (режим `single`).

Если описание оставили пустым, в качестве исходного запроса фиксируется автотекст: `Channels similar to <референсы через запятую>` либо `Channels similar to <ссылка>`.

## 4. Жизненный цикл sourcing

1. По `Start sourcing` создаётся задача подбора: назначение, исходный запрос, ссылка-источник, фильтры, статус `pending`, дата создания.
2. Модалка закрывается, показывается тост:
   - в существующую коллекцию: `Sourcing started — channels will be added to “<коллекция>”`;
   - новая коллекция: `Sourcing started — we're finding channels`.
3. В хедере появляется пилюля **`Sourcing in progress`**:
   - счётчик, если параллельно идёт больше одной задачи;
   - список задач: имя коллекции, `Cancel`, `View` (ведёт в представление коллекции);
   - `Cancel` снимает задачу, тост `Sourcing of “<коллекция>” canceled`.
4. По завершении статус `created` и тост:
   - новая коллекция: `Sourcing finished — “<коллекция>” is ready`;
   - дописывание: `Added N channels to “<коллекция>”` и, если часть каналов уже была, `· M already there` (дедуп по составу коллекции обязателен).
5. Найденные каналы попадают в состав коллекции, коллекция появляется в My collections.

В прототипе подбор имитируется фиксированной задержкой 5 секунд и фиксированным списком найденных каналов. **На проде это долгая асинхронная задача**: нужен статус задачи, устойчивость к перезагрузке страницы и к уходу со страницы, обработка ошибки подбора (в прототипе состояния ошибки нет — см. «Открытые вопросы»).

## 5. Представление результата

Открывается из пилюли (`View`) и из My collections. Показывает:

- бейдж **`AI collection`** — только у коллекций, созданных подбором (у обычной коллекции, куда просто дописали каналы, бейджа нет);
- блок с исходным `Query` и чипами применённых фильтров — то, по чему набирались каналы;
- для обычной коллекции с дописанными каналами источник тоже сохраняется и показывается (чтобы было видно, откуда там эти каналы).

## 6. Режимы поиска на Basic data (контекст, влияет на UX подбора)

В строке поиска Basic data — переключатель режима слева от поля:

| Режим | Описание в меню |
| --- | --- |
| `AI semantic search` (по умолчанию, бейдж `Default`) | `Search by meaning and topic. Example: "travel" find travel channels even without the word in titles.` |
| `Traditional search` | `Exact match by channel name, link or UC id.` |

Поведение: режим определяется автоматически по вводу — ссылка, `@handle`, `UC…`-id или домен youtube переключают на `Traditional search`, всё остальное — на `AI semantic search`. Как только пользователь выбрал режим руками, автопереключение больше не срабатывает до конца сеанса. Справа в поле — крестик очистки, появляется при непустом значении.

## 7. Состояния и краевые случаи

| Ситуация | Ожидаемое поведение |
| --- | --- |
| Нет ни одной коллекции | В модалке только поле имени новой коллекции |
| Коллекция уже в подборе | В дропдауне назначения недоступна для выбора |
| Дубль референса | Не добавляется, поле очищается |
| Удалили все референсы | Генерация описания отменяется, поле остаётся с тем, что уже сгенерировано |
| Пользователь правит сгенерированное описание | Правки сохраняются, повторная генерация только по явному действию (изменение референсов / `Auto-fill`) |
| Несколько подборов одновременно | Все в пилюле со счётчиком, каждый отменяется отдельно |
| Дописывание в коллекцию, где часть каналов уже есть | Добавляются только новые, в тосте количество добавленных и пропущенных |
| Уход со страницы / перезагрузка во время подбора | Задача не теряется, пилюля восстанавливается |
| Подбор ничего не нашёл | **Не определено** — см. «Открытые вопросы» |
| Подбор упал с ошибкой | **Не определено** — см. «Открытые вопросы» |

## 8. Что нужно от бэкенда

| Метод | Назначение | Вход | Выход |
| --- | --- | --- | --- |
| Создать задачу подбора | Запуск sourcing | назначение (id существующей коллекции или имя новой), описание, ссылка-источник, список референсов, фильтры (subs / videos / views / avg / lastDays) | id задачи, статус |
| Статус задачи | Пилюля и переход в результат | id задачи | статус (`pending` / `done` / `failed`), прогресс (если есть), количество найденных |
| Результат задачи | Состав коллекции после подбора | id задачи | список каналов, сколько добавлено, сколько пропущено как дубли |
| Отмена задачи | Кнопка `Cancel` в пилюле | id задачи | — |
| Автодополнение каналов | Подсказки в поле референса | строка поиска | список каналов (id, название, аватар) |
| Черновик описания (LLM) | `Auto-fill` и генерация по референсам | ссылка **или** список референсов | текст описания |
| Похожие каналы | Возможное переиспользование | id канала | список похожих каналов (эндпоинт уже есть на проде) |

Дополнительно к обсуждению с бэкендом: парсинг и валидация ссылки на канал (`https://…`, `youtu.be`, `@handle`, `UC…`), лимиты по тарифу (сколько подборов в месяц / сколько каналов за подбор), поведение при исчерпании лимита.

## 9. Трекинг MixPanel

Теги ниже — **новые**, в спеке `MixPanel Data Track Event List` их пока нет. Схема и правила взяты оттуда: домен для этих событий — `analytics`, обязательна воронковая пара `-open` / `-submit`, один intent = один `action-*` + разные `source-*`.

| Тег | Модификаторы | Элемент |
| --- | --- | --- |
| `action-analytics-ai-sourcing-open` | `source-basic-data-header`, `source-collections-header` | Кнопка `AI collection` |
| `action-analytics-ai-sourcing-open` | `source-basic-footer` | Кнопка `Find similar channels` в футере выбора |
| `action-analytics-ai-sourcing-submit` | `kind-new`, `kind-existing` | Кнопка `Start sourcing` |
| `action-analytics-ai-sourcing-cancel` | — | Кнопка `Cancel` в модалке |
| `action-analytics-ai-autofill` | — | Кнопка `Auto-fill` |
| `action-analytics-ai-reference-add` | `kind-link`, `kind-suggest` | Добавление reference-канала |
| `action-analytics-ai-reference-remove` | — | `×` на чипе референса |
| `action-analytics-ai-advanced-open` | — | Раскрытие `Advanced filters` |
| `action-analytics-ai-job-cancel` | `source-header-pill` | `Cancel` в пилюле `Sourcing in progress` |
| `action-analytics-ai-job-view` | `source-header-pill` | `View` в пилюле |
| `action-analytics-search-mode-select` | `kind-semantic`, `kind-traditional` | Выбор режима поиска на Basic data |

Field-теги (autocapture): `field-ai-sourcing-name`, `field-ai-sourcing-query`, `field-ai-sourcing-reference`, `field-ai-sourcing-min-subs`, `field-ai-sourcing-min-videos`, `field-ai-sourcing-min-views`, `field-ai-sourcing-min-avg`, `field-ai-sourcing-last-days`.

Обязательное следствие: после согласования имена нужно внести в разделы 2–3 страницы `MixPanel Data Track Event List` и синхронизировать `docs/MIXPANEL_GUIDE.md` в том же PR. Документ с таблицей новых событий передать тимлиду Олегу Кравцу для обновления Notion.

## 10. Открытые вопросы

1. Пустой результат подбора: что показываем в коллекции и в тосте?
2. Ошибка подбора: ретрай, уведомление, статус в пилюле?
3. Сколько времени реально занимает подбор и нужен ли прогресс (в прототипе — 5 секунд без прогресса)?
4. Лимиты по тарифу: количество подборов, размер результата, что видит free-план?
5. Связываем ли существующую прод-страницу `Similar channels` у канала с этим флоу (кнопка «найти похожие → в коллекцию»)?
6. Можно ли перезапустить подбор по уже созданной AI-коллекции (обновить состав по тому же запросу)?
7. Редактируется ли запрос у созданной AI-коллекции?
8. Права: видит ли sourcing-задачу второй пользователь, которому расшарили коллекцию?

## 11. Где смотреть прототип

Кликабельный прототип (локально, `node build/serve.js`, порт 8778):

- `analytics-basic-data.html` — кнопка `AI collection`, режимы поиска, футер выбора с `Find similar channels`;
- `analytics-collections.html` — вход `AI collection` со списка коллекций, статусы коллекций;
- `analytics-deep-data.html?ai=<id>` — представление коллекции с бейджем `AI collection`, исходным запросом и чипами фильтров.

Исходники поведения: `build/build-analytics.js` (разметка модалки, лейблы, тексты) и `js/analytics.js` (флоу: режимы, референсы, генерация описания, запуск и жизненный цикл подбора). Все UI-строки в этом документе взяты из них дословно.
