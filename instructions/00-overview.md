## Что мы строим

Полностью статический (HTML/CSS/JS, без Node/backend/сборки для просмотра) кликабельный прототип фронтенда SubSub, визуально и структурно соответствующий реальному продакшену. Нужен продуктовому дизайнеру, чтобы кликать по экранам продукта без необходимости поднимать реальный бэкенд/окружение.

Результат живёт в: `E:\Dev SubSub\subsub_front_prototype_14.07.26`

## Почему так, а не иначе (контекст из предыдущей сессии)

1. Изначально пытались взять существующий Storybook из `E:\Dev SubSub\subsub_platform_front\layers\core\.storybook` — оказалось, что он покрывает только базовые UI-компоненты (кнопки, инпуты, диалоги), не реальные экраны продукта, и **не гарантированно соответствует текущему проду** (устаревал независимо от прода). Дизайнер явно сказал: не использовать его как источник для этого прототипа.
2. Пытались собрать прототип как один большой HTML-файл с JS-рендерингом карточек/навигации через `innerHTML` шаблоны — сломалось молча (пустой сайдбар, пустые карточки) из-за ошибки в JS-шаблоне, которую не видно на глаз. Вывод: **не делать так** — см. `03-known-pitfalls.md`.
3. Пытались подключать иконки как отдельный `.js`-файл рядом с HTML — пользователь не смог открыть "папку с иконками" (видимо, спутал файл с папкой, или файл не считался частью прототипа). Вывод: либо класть иконки как обычные файлы изображений в подпапку `icons/`, либо (если встраивать) — встраивать прямо в HTML одним файлом, без отдельного JS-файла с невнятным именем.

## Источник истины

**Продакшен: https://app.subsub.io/home (и другие страницы под app.subsub.io).** Не Storybook, не документация в репозитории — они могут быть устаревшими. Репозиторий `subsub_platform_front` — вторичный источник: точные тексты (i18n), дизайн-токены (цвета/типографика), список реальных иконок-файлов. Подробнее — `01-source-of-truth-and-workflow.md`.

## Формат работы

Постранично. Не пытаться сделать "всё сразу". Начинаем с Home (`https://app.subsub.io/home`) и останавливаемся после каждой страницы для проверки пользователем, прежде чем переходить к следующей. См. `01-source-of-truth-and-workflow.md`.

## Что НЕ входит в задачу

- Не трогать `E:\Dev SubSub\subsub_platform_front` — это отдельный настоящий репозиторий (Nuxt-приложение), используется только для чтения (тексты, токены, файлы иконок). Его собственный беспорядок (устаревшие докстрока, несоответствия) — отдельная задача, не блокирует эту.
- Не нужен реальный бэкенд, авторизация, живые данные. Везде, где данные должны приходить с сервера (таблицы, баланс, графики) — статичные/примерные значения, явно выглядящие как прототип, а не как реальные цифры пользователя.
- Не нужен Node/npm/build step для *просмотра* готового прототипа — он должен открываться прямо в браузере из файлов.

## Definition of done для очередной страницы

- Все текстовые блоки, которые есть в реальной статике страницы (баннеры, заголовки, описания, чек-листы, FAQ и т.п.) — реальный текст 1:1, а не выдуманный.
- Структура/иерархия блоков соответствует реальной странице (что видно в DevTools на проде).
- Навигация (сайдбар) кликабельна и ведёт на другие собранные страницы прототипа.
- Открыт в браузере и визуально сверен с https://app.subsub.io — расхождения зафиксированы или исправлены.
- Пользователь посмотрел и подтвердил, что можно двигаться дальше.
