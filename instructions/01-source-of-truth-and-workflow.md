# Источник истины и порядок работы

## Иерархия источников

1. **Живой прод — https://app.subsub.io** (главный источник). Открывать через Claude in Chrome (расширение уже должно быть подключено; пользователь упоминал, что дополнительно подключит Windows MCP для доступа к режиму разработчика — если он доступен, использовать его аналогично `javascript_tool`/DevTools ниже).
2. **Репозиторий `E:\Dev SubSub\subsub_platform_front`** (только на чтение) — для:
   - точных текстов (i18n): `layers/core/i18n/locales/en/*.ts`
   - дизайн-токенов: `layers/core/assets/css/main.css` (блок `@theme`)
   - реальных файлов иконок: `layers/core/assets/images/*.webp`
   - понимания структуры навигации: `apps/app.subsub/app/components/spacesMenu/composables/useSpacesDictionary.ts`
   - структуры страниц: `apps/app.subsub/app/pages/**`
3. **Storybook в репозитории (`layers/core/.storybook`)** — НЕ использовать как источник истины для этого прототипа. Он покрывает только базовые компоненты и может отставать от прода. Если нужно свериться с ним — только как второстепенную подсказку, финальная проверка всегда против живого прода.

При конфликте между репозиторием и живым продом — **прод побеждает**. Репозиторий мог уйти вперёд или отстать от того, что реально задеплоено.

## Как безопасно вытаскивать данные с прода через DevTools/JS

Работает через `javascript_tool` (Claude in Chrome) или аналогичный DevTools-доступ. Проверено в предыдущей сессии:

- **Не** дампить `element.outerHTML` целиком с продовой страницы — расширение блокирует такие ответы ("[BLOCKED: Cookie/query string data]"), видимо из-за токенов/query-параметров где-то в дереве.
- Вместо этого — точечно вытаскивать: `tagName`, `className`/`getAttribute('class')`, `textContent` листовых узлов, `getAttribute('d')` у `<path>` (для SVG-иконок), `getAttribute('src')` у `<img>` (для растровых иконок — обычно можно взять только имя файла, сам файл лучше брать из репозитория, а не с прода).
- Если результат обрезается (`[TRUNCATED]`) — сужать запрос (конкретный элемент/атрибут), а не пытаться получить всё за один раз.
- Перед кликом по элементу на свежей странице — подождать после `navigate` (нужна гидрация SPA), иначе клик может просто не сработать молча. Надёжнее — `find` (по описанию элемента) или `javascript_tool` с прямым вызовом клика/навигации через DOM, чем клик по координатам.

## Порядок работы — постранично

Для КАЖДОЙ страницы, в этом порядке:

1. **Выбрать одну страницу** (первая — Home, `https://app.subsub.io/home`). Не пытаться сделать сразу несколько.
2. **Открыть страницу на проде** через Claude in Chrome, авторизация уже должна быть (в прошлой сессии сессия уже была залогинена как Yevhenii Zemskov).
3. **Извлечь реальную структуру** нужного участка: классы, текст, иконки — точечными JS-запросами (см. выше).
4. **Сверить с репозиторием**: найти соответствующий `.vue`-компонент в `apps/app.subsub/app/pages/**` и i18n-файл в `layers/core/i18n/locales/en/**` — взять оттуда точный текст (он надёжнее, чем читать текст со скриншота) и понять, какие классы — оформление компонента, а какие — просто layout/размер на вызывающей стороне.
5. **Написать статичный HTML** для этой страницы как обычный `.html`-файл (без JS-шаблонов для статичного контента — см. `02-tech-approach.md` и `03-known-pitfalls.md`), используя общий `styles.css` и реальные файлы иконок.
6. **Открыть в браузере и сверить визуально** с живым продом (можно рядом, можно через скриншот прода в чате — просто для сравнения глазами; сохранять скриншоты прода как файлы через Claude in Chrome в этой среде не получалось, см. пункт про `save_to_disk` в `03-known-pitfalls.md`).
7. **Показать пользователю, дождаться подтверждения**, прежде чем переходить к следующей странице. Обновить `05-progress.md`.
