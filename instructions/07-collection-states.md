# Состояния коллекции

Документ описывает логику состояний. **Реализовано в прототипе 12.08.2026** — см. раздел «Как это сделано».
Лейблы и тексты тултипов ждут утверждения.

## Главное правило

**`Collecting channels` и `Collecting deep data` никогда не идут одновременно по одной коллекции.**
Пока активно одно, вход во второе **заблокирован с тултипом-объяснением, а не спрятан**.

Правило работает **внутри коллекции**, не глобально: по одной коллекции может идти подбор,
по другой в тот же момент — сбор Deep data.

В проде сейчас один статус `Collecting data`. Здесь он расщепляется на два — это осознанное
расхождение с продом, а не недоделка.

## Состояния

### 1. Created

Коллекция есть, каналы могут быть или не быть, Deep data не активирована, фоновых процессов нет.

- **Можно:** запустить подбор каналов; активировать Deep data (нужен минимум 1 канал);
  добавлять и удалять каналы вручную; переименовать, шарить, дублировать, удалить.
- **Deep data:** пустое состояние с кнопкой активации.

### 2. Collecting channels

Идёт подбор каналов, они появляются постепенно.

- **Можно:** добавлять и удалять каналы вручную; отменить подбор; переименовать, шарить;
  смотреть уже подобранное, не дожидаясь финала.
- **Нельзя:** активировать Deep data (тултип «дождитесь окончания подбора каналов»);
  запустить второй подбор; `Find similar channels` в эту коллекцию;
  выбрать её получателем в Create Collection — пункт disabled.
- **Deep data:** пустое состояние, активация заблокирована.

### 3. Collecting deep data

Идёт сбор глубоких метрик по текущему набору каналов.

- **Можно:** отменить сбор (`Cancel` или `Deactivate`) с возвратом в Created; переименовать, шарить;
  смотреть прогресс.
- **Нельзя:** запускать подбор каналов — все входы заблокированы (досорсер на странице коллекции,
  `Find similar channels`, выбор получателем); добавлять и удалять каналы вручную.
- **Deep data:** состояние сбора с прогрессом — не нули и не скелетон на месте данных.

### 4. Activated

Deep data собрана, коллекция рабочая, фоновых процессов нет.

- **Можно:** всё из Created; открыть Deep data с данными и экспортировать;
  `Deactivate` с возвратом в Created.
- **С предупреждением:** добавление каналов и запуск подбора — блокирующий диалог
  «данные по новым каналам будут неполными и начнутся со дня добавления» с кнопками
  «Добавить всё равно» и «Дублировать коллекцию и активировать заново».

**—** не применимо

| Действие | Created | Collecting channels | Collecting deep data | Activated |
| --- | --- | --- | --- | --- |
| Добавить каналы вручную | ✅ | ✅ | 🔒 «нельзя менять состав, пока идёт сбор Deep data» | ⚠️ диалог о неполных данных |
| Удалить канал / массово | ✅ | ✅ | 🔒 то же | ✅ данные по удалённым уходят из Deep data |

| `Find similar channels` в эту коллекцию | ✅ | 🔒 «подбор уже идёт» | 🔒 «дождитесь окончания сбора Deep data» | ⚠️ диалог о неполных данных |
| Выбрать получателем в Create Collection | ✅ | 🔒 пункт disabled с тултипом | 🔒 пункт disabled с тултипом | ⚠️ диалог о неполных данных |
| Активировать Deep data | ✅ (при 0 каналов 🔒 «добавьте хотя бы один канал») | 🔒 «дождитесь окончания подбора каналов» | — уже идёт | — уже активирована |

| Открыть Deep data | ✅ пустое состояние с кнопкой активации | ✅ пустое состояние, активация заблокирована | ✅ состояние сбора с прогрессом | ✅ данные |
| Export | 🔒 «нужна собранная Deep data» | 🔒 то же | 🔒 то же | ✅ |
| Переименовать | ✅ | ✅ | ✅ | ✅ |
| Share | ✅ | ✅ | ✅ | ✅ |
| Duplicate | ✅ | открытый вопрос 2 | открытый вопрос 2 | ✅ |
| Delete | ✅ | ✅ удаление отменяет процесс | ✅ удаление отменяет процесс | ✅ |
| `Cancel` процесса | — | ✅ | ✅ | — |
| Выбрать в селекторе коллекций | ✅ | ✅ | ✅ | ✅ |

**Отдельно:** выбрать в селекторе можно **любую** коллекцию, включая неактивированную —
она ведёт в состояние с кнопкой активации, а не дизейблится. Дизейбл пункта селектора
не используем ни в одном состоянии.

`Delete` доступен во всех состояниях (в списках «Можно» состояний 2 и 3 он не назван —
считаем это умолчанием: удаление коллекции отменяет её процесс). Если правило другое — правим.

## Переходы

| Из | Событие | В |
| --- | --- | --- |
| — | коллекция создана | Created |
| Created | запустил подбор | Collecting channels |
| Collecting channels | подбор завершён | **Created**, не Activated — Deep data активирует пользователь сам |
| Collecting channels | `Cancel` | Created, подобранное остаётся |
| Collecting channels | ничего не нашёл | Created, коллекция пустая |
| Collecting channels | ошибка | Created, сообщение, повтор |
| Created | активировал Deep data | Collecting deep data |
| Collecting deep data | сбор завершён | Activated |
| Collecting deep data | `Cancel` или `Deactivate` | Created |
| Collecting deep data | ошибка | Created, сообщение, повтор |
| Activated | `Deactivate` | Created |
| Activated | добавил каналы → «Добавить всё равно» | Activated, у новых каналов истории нет |
| Activated | добавил каналы → «Дублировать и активировать заново» | Activated + дубль в Created; дубль сразу уходит в Collecting deep data |
| Activated | запустил подбор | Collecting channels, по завершении обратно Activated |

## Где показываем

- **Список My collections** — пилюля в колонке `STATUS` и действие рядом с ней:
  Created → `Activate deep data`, Activated → `View deep data`,
  состояния сбора → прогресс и `Cancel`.
- **Страница коллекции** — плашка состояния сверху, у заголовка; состояние кнопок по матрице.
- **Селектор коллекций на Basic data и Deep data** — различает все четыре состояния,
  до выбора видно, где Deep data готова. Ничего не дизейблим.
- **Пилюля в шапке** — только два состояния сбора: счётчик процессов, по каждому имя коллекции,
  `Cancel`, `View`.
- **Страница Deep data** — по строке «Открыть Deep data» из матрицы: пустое состояние с активацией,
  пустое с заблокированной активацией, состояние сбора с прогрессом, данные.

## Краевые случаи

- **Активация коллекции с 0 каналов** — заблокировать, тултип «добавьте хотя бы один канал».
- **Подбор ничего не нашёл** — Created + пустое состояние, промпт виден, кнопка досорсить.
- **Ошибка подбора или сбора** — Created + сообщение + повтор. Коллекцию нельзя оставлять
  в состоянии процесса.
- **Несколько коллекций в процессе одновременно** — разрешено (правило действует внутри коллекции).
- **Чужая (sample) коллекция** — состояние только читается, изменяющих действий нет.
- **Удалили каналы после активации** — коллекция остаётся Activated, данные по удалённым каналам
  исчезают из Deep data.

## Решённые вопросы (13.08.2026)

1. **Лейблы:** подбор — `Sourcing channels`, сбор Deep data — прежний продовый `Collecting data`.
   `Created` и `Activated` без изменений.
2. **Правка состава:** оставляем несимметрично — во время подбора состав менять можно,
   во время сбора Deep data нельзя (сбор идёт по фиксированному набору каналов).
3. **Duplicate во время процесса:** заблокирован до окончания, пункт виден с тултипом
   «Wait until the running process finishes».
4. **Cancel сбора Deep data:** собранное отбрасывается полностью, коллекция возвращается
   в Created, повторная активация собирает заново.

## Тексты (на утверждение)

| Место | Текст |
| --- | --- |
| Активация во время подбора | Wait until channel sourcing finishes |
| Подбор во время сбора Deep data | Wait until deep data collection finishes |
| Правка состава во время сбора | Channels can’t be changed while deep data is being collected |
| Активация пустой коллекции | Add at least one channel first |
| Export без собранных данных | Deep data isn’t collected yet |
| Duplicate во время процесса | Wait until the running process finishes |
| Кнопка Deep data во время сбора | Deep data is being collected — open Deep data to see progress |
| Отмена подбора (тост) | Sourcing cancelled — “Имя” |
| Отмена сбора (тост) | Deep data collection cancelled — “Имя” |
| Сбор завершён (тост) | Deep data is ready — “Имя” |

Ошибки подбора и сбора в прототипе не смоделированы — состояний ошибки нет,
тексты для них ждут решения вместе с реализацией.

## Правки 13.08.2026 (реализовано)

- **Вместимость коллекции — тарифная:** Explorer 10, Pro 25, Business 100, Enterprise без лимита. Счётчик на странице коллекции показывает эти числа (было зашито 30 — это лимит вставки за один раз, он живёт отдельно в модалке добавления). У Enterprise плашка мест и апселл не показываются вовсе.
- **Sample-коллекции:** не считаются в лимит числа коллекций и активированы для всех планов — на Explorer Deep data по сэмплу открыта, по своей коллекции кнопка видна и заблокирована с апселлом `Deep data is available on Pro and above — upgrade to activate`.
- **Добавление каналов** во время подбора запрещено полностью: кнопка `Add channels` на странице коллекции заблокирована с тултипом `Sourcing is running — it fills the collection itself`, а сама коллекция недоступна получателем в модалках выбора. Удаление во время подбора разрешено.
- **Удалённый во время подбора канал** попадает в исключения подбора для этой коллекции: `aiFoundLeft` фильтрует список найденного по `subsub_coll_removed`, поэтому подбор его не возвращает. Вручную добавить обратно можно.
- **Разные подписи:** во время сбора Deep data пункт меню — `Stop collecting`, у активированной — `Deactivate collection`.
- **Блок последнего подбора** (`Last sourcing` + `Filters used` + `Source more channels`) вынесен на страницу коллекции. Он не показывался, потому что жил только в разметке Deep data и зависел от `?ai=` в ссылке либо от `extra[name].sourcing`, который записывался лишь когда приезжал первый канал. Теперь параметры пишутся при запуске подбора, а имя коллекции берётся из заголовка страницы. Досорсинг открывает модалку с предзаполненным промптом и фильтрами последнего запуска.
- **Скелетоны:** не больше трёх строк «ещё ищем» независимо от заказанного количества. У только что добавленного канала в ячейках метрик заглушка вместо прочерка.
- **Демо:** `subsubPlan("explorer" | "pro" | "business" | "enterprise")` переключает тариф, `subsubState(name, state)` — состояние коллекции, `subsubFast(true)` ускоряет процессы.
